> 날짜: 2026-03-22

## 🎨 UI/UX

**레이아웃이 너무 좁고 가운데 쏠림**
- 전체 콘텐츠가 화면 가운데 좁은 컬럼에만 몰려 있고, 양쪽에 검정 여백이 많아요. `st.set_page_config(layout="wide")`를 활용하거나, 날씨 지표 4개(기온/강수량/습도/풍속)를 가로로 나란히 배치하면 훨씬 보기 좋습니다.

**날씨 지표가 세로로 쌓여 있음** ✅ 반영
- 기온, 강수량, 습도, 풍속이 `st.metric()`으로 각각 세로로 나열되어 있는데, `st.columns(4)`로 가로 배치하면 한눈에 비교하기 쉬워져요.

**"🌏 지구 반대편은?" 섹션이 어색함**
- 텍스트가 `keyboard_arrow_right`라는 Material Icon 코드명이 그대로 렌더링되어 보입니다. (현재 코드에서는 이미 `st.expander`로 수정되어 있음 — 해당 없음)

**다크모드 고정**
- 현재 CSS로 강제 다크 테마인데, 사용자 시스템이 라이트 모드일 경우 Streamlit 기본 UI 컴포넌트와 어긋날 수 있어요. 라이트/다크 토글을 사이드바에 추가하거나, Streamlit config에서 `theme`을 통일하는 게 좋습니다.

## 📊 데이터 시각화

**이상치 차트 — 범례가 "color"라고 나옴** ✅ 반영
- Plotly 차트의 범례 제목이 `color`로 표시되고 있어요. `fig.update_layout(legend_title_text="구분")` 추가.

**산점도의 상관관계 해석 안내 부재** ✅ 반영
- 기온 vs 지하철 이용객 산점도에서 Pearson -0.12, Spearman -0.14는 "거의 상관없음" 수준인데, 이 수치가 뭘 의미하는지 해석 텍스트 없이 숫자만 던져져 있어요. 한 줄 해석 추가.

**이상치 탐지 — 어떤 알고리즘인지 안 보임**
- scikit-learn을 쓴다고 footer에 나와 있지만, IsolationForest인지 Z-score인지 LocalOutlierFactor인지 전혀 표시가 없어요. 차트 아래 작은 글씨로라도 알고리즘 명칭과 파라미터를 표기하면 신뢰도가 올라갑니다.

## ⚙️ 기능/UX 흐름

**역/도시 선택이 하드코딩**
- 문정역과 몬테비데오가 고정값이에요. 사이드바에 역 선택(서울 지하철 역명 selectbox)이나 최소한 "다른 역으로 바꾸기" 기능이 있으면 재사용성이 크게 높아집니다.

**"Claude 협업 타임라인 — 준비 중" 섹션**
- 준비 중인 기능은 아예 숨기거나, `st.expander` 안에 넣어 완성된 것처럼 보이지 않게 하는 게 나아요.

**데이터 갱신 시점 표시 없음**
- 현재 날씨 데이터가 언제 기준인지 표시가 없어요. 마지막 API 호출 시간을 header 근처에 작게 표시하면 신뢰도가 올라갑니다.

## 🧹 코드/구조

**CSS 주입 방식**
- `st.markdown("""<style>...</style>""", unsafe_allow_html=True)`로 CSS를 직접 주입하는 것은 Streamlit 업데이트 시 `data-testid`가 바뀌면 깨질 수 있어요.

**폰트 외부 로드 의존성**
- Google Fonts를 `@import`로 불러오는데, 오프라인이나 사내망 환경에서는 폰트가 로드되지 않아 UI가 흐트러질 수 있어요. fallback 폰트를 명확히 지정해 두세요.
